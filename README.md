# Restaurant TMA

Telegram Mini App для заказа еды из ресторана: мини-апп для клиентов, бот (клиенты + курьеры) и админка.

## Структура

```
apps/
  miniapp/   Vue 3 + Vite + Pinia + Tailwind — клиентское приложение внутри Telegram
  api/       Fastify + grammY + Prisma — REST API и бот в одном процессе
  admin/     Vue 3 + Vite + Tailwind — веб-админка (порт 5180)
packages/
  shared/    типы, общие для всех приложений
```

## Быстрый старт

```bash
pnpm install
cp .env.example apps/api/.env      # вписать BOT_TOKEN от @BotFather
cp .env.example apps/miniapp/.env  # оставить только VITE_* строки
pnpm --filter api db:migrate       # создаёт SQLite базу
pnpm --filter api db:seed          # тестовое меню
pnpm dev                           # API :3000, мини-апп :5173, админка :5180
```

Админка: `http://localhost:5180`, логин и пароль из `ADMIN_LOGIN` / `ADMIN_PASSWORD` в `apps/api/.env`.

Без Telegram мини-апп открывается в обычном браузере на `http://localhost:5173`:
при `ALLOW_DEV_AUTH=true` API принимает заголовок `Authorization: dev <telegramId>` вместо настоящей подписи.

## Открыть на телефоне (браузер, без Telegram)

Телефон и компьютер в одной Wi-Fi сети. После `pnpm dev` Vite печатает строку `Network: http://192.168.x.x:5173` — этот адрес открыть на телефоне.
Запросы к API идут через прокси Vite (`/api` → `localhost:3000`), поэтому отдельно открывать порт 3000 не нужно.

## Запуск внутри Telegram (dev)

Telegram открывает мини-апп только по HTTPS, поэтому нужен туннель до Vite:

```bash
cloudflared tunnel --url http://localhost:5173
```

Полученный `https://…trycloudflare.com` записать в `MINIAPP_URL` в `apps/api/.env` и перезапустить API.
Бот сам установит кнопку меню и будет отвечать на `/start` кнопкой «Открыть меню».

## Карта для адреса доставки

Клиент выбирает точку на Яндекс.Карте (`vue-yandex-maps`), адрес определяется через HTTP Геокодер и сохраняется вместе с координатами.
Нужен один бесплатный ключ «JavaScript API и HTTP Геокодер» с https://developer.tech.yandex.ru/services/ — вписать его в
`VITE_YANDEX_MAPS_KEY` (`apps/miniapp/.env`) и `YANDEX_MAPS_KEY` (`apps/api/.env`). Без ключа кнопка «Добавить адрес» открывает обычную форму.

## Админка

Разделы: обзор (статистика, активные заказы), заказы (фильтры, смена статуса, назначение курьера, ссылка на карту),
меню (категории, блюда, фото, наличие, хит/новинка, порядок), баннеры, клиенты (роли клиент/курьер/админ, блокировка), настройки ресторана.
Новые заказы подсвечиваются в боковом меню и сопровождаются звуковым сигналом (страница должна быть открыта).
Загрузка фото: `POST /api/admin/upload`, файлы лежат в `apps/api/uploads` и отдаются по `/uploads/...`.

## Авторизация

- Мини-апп на каждый запрос шлёт `Authorization: tma <initData>`; сервер проверяет HMAC-подпись Telegram, сессий и JWT нет.
- Имя и username берутся из `initData`, пользователь создаётся автоматически при первом запросе.
- Телефон запрашивается одной кнопкой через `WebApp.requestContact()`; подписанный ответ отправляется на `POST /api/me/phone` и проверяется той же схемой.

## Дизайн

Палитра задаётся токенами в `apps/miniapp/src/style.css` (`--bg`, `--accent` и т.д.), Telegram-тема не используется, чтобы приложение выглядело одинаково у всех.
Фон приложения — `--bg`, одна строка меняет оттенок для всего приложения. Нижняя навигация — «жидкое стекло»: `backdrop-filter` + пружинная анимация индикатора (`.glass-nav` в том же файле).
Фото блюд в тестовых данных — с Unsplash; в админке их заменят на фотографии ресторана.

Экраны: Главная, Меню, Блюдо, Корзина, Избранное, Профиль, Поиск, Мои заказы, Мои адреса, Статус заказа.

## Решения по продукту

- У блюда одна цена и одна порция, без размеров и модификаторов.
- Пожелания к блюду — свободный текст на каждой позиции корзины. Одно блюдо с разными комментариями это разные строки.
- Доставка и самовывоз. Оплата: наличные / перевод (онлайн-оплата позже).
- Корзина хранится в Telegram CloudStorage, на сервер уходит только готовый заказ; цены пересчитываются на сервере.
- Статусы: `new → accepted → cooking → delivering → completed` для доставки, `new → accepted → cooking → ready → completed` для самовывоза, `cancelled` из любого незавершённого.

## API

| Метод | Путь | Что делает |
| --- | --- | --- |
| GET | `/api/catalog` | категории, блюда, баннеры, настройки, открыт ли ресторан |
| POST | `/api/me` | профиль (создаёт при первом входе) |
| PATCH | `/api/me` | имя, язык |
| POST | `/api/me/phone` | сохранить телефон из `requestContact` |
| GET/POST/DELETE | `/api/me/addresses[/:id]` | адреса, `POST /:id/default` — основной |
| GET/PUT/DELETE | `/api/me/favorites[/:dishId]` | избранное |
| POST | `/api/orders` | создать заказ |
| GET | `/api/orders[/:id]` | мои заказы |

## База данных

Dev: SQLite (`apps/api/prisma/dev.db`). Для продакшена в `schema.prisma` заменить `provider = "sqlite"` на `"postgresql"`, обновить `DATABASE_URL` и пересоздать миграции.
